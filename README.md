# IThub academic performance

Сервис импортирует отчёты успеваемости из Excel в PostgreSQL и формирует документы на основе данных БД.

## Запуск

```bash
npm install
npm run dev
```

Перед запуском проверьте `DATABASE_URL` в `.env`. Контракт базы находится в `src/prisma/contract.prisma`; после его изменения обновите артефакты командой `npm run prisma:contract:emit` и примените миграции командой `npm run prisma:db:migrate`.

## Импорт

Откройте `/` и загрузите `.xlsx`-выгрузку. Импорт читает лист «Отчет» и сохраняет записи успеваемости вместе с партией загрузки.

### Учебные планы

`POST /api/import/study-plan` принимает JSON с данными, извлечёнными из PDF. Программа, группы и календарные семестры указываются по существующим идентификаторам в БД. План определяется тройкой `studyProgramId`, `admissionBase`, `admissionYear`. Для базы 9 класс создаются семестры 1–8, для базы 11 класс — 1–6.

```json
{
  "studyProgramId": 1,
  "admissionBase": 9,
  "admissionYear": 2024,
  "sourceFileName": "УП 09.02.07 ПРОГР 3,10 25-26.pdf",
  "disciplines": [
    { "code": "ОУП.01", "name": "Русский язык", "semester": 1, "controlForms": ["Контрольная работа"] },
    { "code": "ОУП.01", "name": "Русский язык", "semester": 2, "controlForms": ["Экзамен"] }
  ],
  "studyGroupIds": [10]
}
```

Для каждой пары «индекс ФГОС и номер семестра» передайте одну строку. Числа в столбцах 3, 4 и 5 означают семестры экзамена, дифференцированного зачёта и контрольной работы или иной формы промежуточной аттестации соответственно. Если для одного семестра указано несколько форм, передайте их в одном массиве `controlForms`. Значение пятого столбца уточняется по примечаниям конкретного плана. Поля `name`, `sourceFileName`, `plannedHours` и `studyGroupIds` необязательны. `admissionYear` — год поступления потока, указанный отдельно от учебного года в заголовке PDF.

Повторная загрузка дополняет план и обновляет переданные часы и метаданные. `studyGroupIds` связывает перечисленные группы с импортируемым учебным планом. Несколько форм контроля хранятся отдельными строками `StudyPlanDiscipline`. Должности сотрудников задаются через справочник `positions` и связующую таблицу `employee_positions`.

## Экспорт

Откройте `/exports` и выберите документ. Для ведомости по дисциплине укажите группу, семестр, дисциплину и форму контроля. Специальность и квалификация берутся из программы группы или из формы. Подпись семестра берётся из исходного импорта.

Оценка в ведомости берётся из поля «Конечные баллы (5-зн система)». Если один и тот же студент повторно импортирован для той же дисциплины и семестра, используется запись из последней загрузки.

### API остальных документов

- `GET /api/export/documents` возвращает идентификаторы и имена файлов.
- `GET /api/export/document-students?groupId=1&semesterId=2` возвращает студентов для персональных документов.
- `POST /api/export/documents/:id` возвращает файл Excel или Word. В JSON можно указать `groupId`, `semesterId`, `disciplineId` и `studentId`. Для выбора студента нужны группа и семестр. Пустой запрос формирует черновик.

Генератор читает доступные записи из PostgreSQL. В черновиках отсутствующие сведения обозначены как `[Нет данных: …]`. Сводная ведомость показывает дисциплины с записями успеваемости. Для её полного заполнения нужны учебный план на семестр и формы контроля. Результаты экзаменов по ПМ и оценки за защиту курсовых требуют отдельных сведений.
